02Project Structure, Explained

  • styles/ — one flat CSS-custom-property design system (tokens.css) shared by all three portals, replacing Player's original Tailwind/Material-Design-3 tokens without adding Tailwind as a dependency.
  • context/ — ThemeContext (persisted theme), AuthContext (PHASE 2 ONLY demo session, explicitly commented as non-security), ToastContext (notifications).
  • routes/ProtectedRoute.jsx — a PHASE 2 PLACEHOLDER that only gates the frontend router based on the demo session; carries an explicit comment block stating it is not real access control and will be replaced by verified JWT role checks in Phase 5.
  • layouts/ — one per portal, each composing the shared AppShell with that portal's navigation groups.
  • components/ — 20 shared, portal-agnostic UI building blocks (full list in §04).
  • data/mockData.js — the Phase 2 demo dataset; see §09 for the historical-vs-live separation this file enforces.
  • services/ — one file per domain area; each function either returns mock data today or throws an explicit "not implemented until Phase N" error, so nothing is silently faked as a real API response.
  • pages/ — 30 route-level pages across auth/admin/coach/player, detailed in §05–§07.

Unavoidable visual differences

  • The single-file Admin and Coach prototypes are now split across multiple routed pages — required by the approved information architecture (separate Admin vs User Management, separate Match vs Training Entry, separate Development Plan vs Goal Tracking).
  • Whatever charting approach existed in the prototypes has been standardised on Recharts, the one chart library named in the Phase 2 brief.
  • Player's Tailwind/Material-Design-3 tokens have been re-expressed as CSS custom properties to match Admin/Coach, so all three portals now share one token system instead of two.
  • The Login page's "92% Prediction Accuracy"-style claim has been replaced with honest, clearly-labelled illustrative demo statistics plus a disclaimer sentence, since no model has been trained.
One design language confirmed: every portal imports the same four stylesheets (tokens.css, base.css, components.css, login.css) and the same component library — there is no second, divergent visual system anywhere in the app.

13Manual / Automated QA

A 32-screenshot Playwright walkthrough was run against a production build (npm run build + npm run preview) covering all three portals, both themes, and a mobile viewport (390×844). Representative shots below; the full set was reviewed for layout, data correctness and console errors.

What was verified

  • All 31 routes render without a React error boundary trip or blank page.
  • Light → dark theme toggle works on Login and inside each portal, and persists via localStorage.
  • Forms, modals (incl. Escape-to-close), tabs, confirm dialogs and toasts all function as demo-only interactions with no real persistence, as intended for Phase 2.
  • Recharts renders real computed values (e.g. Player Comparison's bar chart reflects the actual derived batting average/strike rate/AI score for P001, and correctly shows zero/"no data" for players without demo performance records).
  • Responsive behaviour at 390px width: the sidebar collapses into a slide-in drawer with a background scrim, confirmed by manually triggering it via its aria-label="Open navigation" button.
Environment limitation, disclosed for transparency: this sandboxed audit environment has no outbound internet access, so the Google Fonts requests for Inter, JetBrains Mono and Material Symbols Outlined fail (ERR_TUNNEL_CONNECTION_FAILED) and icons render as literal text labels (e.g. "dashboard", "menu") in the screenshots above instead of glyphs. This is a network restriction of this review sandbox only, not a defect in the code — index.html's font <link> tags are correct, and on the user's own machine (npm run dev, normal internet access) the icons and fonts will load and render exactly as in the original four approved prototypes. Recommend a quick local visual check once this lands in the user's own frontend/ folder.
